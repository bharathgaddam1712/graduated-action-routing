## Session Protocol (every Kaggle session)

### At the start
Every notebook's cell 1 calls `init()` which:
1. Copies `src/` from `slm-agents-code` input into the working dir
2. Restores `results/` CSVs from `slm-agents-results` input (resume-safe)
3. Sets HF cache to `slm-agents-models` input (no re-downloads)

### At the end — CRITICAL
Every notebook's last cell calls `save(P['results'])` which:
1. Zips all `results/*.csv` with a timestamp
2. Prints: `Download results_snapshot_*.zip`

**You must then:**
1. Download the zip from the Outputs panel
2. Unzip it and upload the CSV files as a **new version** of `slm-agents-results`
3. Re-attach it to the next notebook session

If you forget: your progress is lost. The next session starts from scratch.

## Resume Safety

All experiment loops use a `done_keys` set:
```python
done_keys = set(zip(df['policy'], df['slm_name'], df['dataset']))
```
If a session crashes mid-run:
1. Start a new Kaggle session
2. Re-attach all three datasets (including the last saved `slm-agents-results`)
3. Re-run the notebook — completed combos are skipped automatically

## Compute Budget

| Step | GPU load | Peak VRAM | Strategy |
|---|---|---|---|
| Baselines | One model at a time | ~6 GB | Load → eval → del/gc after each combo |
| Routing sweeps | LLM resident + swap SLM | ~11 GB | Keep 8B loaded, swap 1.5B per threshold |
| 3-level cascade | Both 1.5B + 3B + 8B | ~14 GB | All three loaded simultaneously |
| Learned router | CPU only | — | Logistic regression takes ~5s |

The 3-level cascade fits on a single T4 (16 GB) but is tight. If you get OOM:
- Reduce `max_steps=6` instead of 8
- Or run the cascade on one T4 and baselines on the other in a separate session

## Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError: src` | `sys.path.insert(0, '/kaggle/working/slm_agents_paper')` before imports |
| `RuntimeError: CUDA out of memory` | Run `del model; gc.collect(); torch.cuda.empty_cache()` then retry |
| BM25 missing | `pip install rank_bm25` |
| HF download fails despite model cache | Check `slm-agents-models` is attached AND `HF_HOME` is set in `session_init.py` |
| `learned_router_auc.txt` shows AUC < 0.6 | Training data too small or one class only; increase Step 2 sample size |
| Step 3 runs very slowly | Only run for one SLM (1.5B) — the other SLM sweep can be a separate session |
| Results CSV is empty after restore | `slm-agents-results` dataset was not updated after last session — re-run from step 2 |

## Verification Checklist (before writing paper)

- [ ] `always_llm` task success > `always_slm_1b` on both datasets (routing worthwhile)
- [ ] At least one routing policy: SR ≥ 90% of oracle at < 60% LLM call ratio
- [ ] `cascade_3lvl` is non-dominated vs best 2-level policy on Pareto frontier
- [ ] Learned router AUC > 0.60 (otherwise fall back to entropy_gate as the ML contribution)
- [ ] Fig 5 (MuSiQue) shows routing benefit generalizes across tasks
- [ ] All 5 figures in `figures/`, all CSVs in `results/`

---

## Fallback Decisions

| If this fails | Then |
|---|---|
| Learned router AUC < 0.6 | Drop it. Use entropy_gate as strongest non-trivial signal. Mention negative result. |
| 3-level cascade does NOT improve 2-level | Keep as negative result: "graduated escalation does not help beyond binary" |
| MuSiQue benefit disappears | Remove MuSiQue. Expand HotpotQA to 500 questions for stronger stats. |
| Verbalized confidence unreliable | Reframe Fig 4 as "entropy outperforms verbalized confidence as routing signal" |
